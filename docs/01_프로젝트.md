# WHENNOTE — 프로젝트 정의

> 순수 메모 데스크톱 앱. 형제 앱 [WHENWORK](../../whenwork/README.md)와 같은 스택·구조·배포 방식을 쓰고, 역할만 나눈다. 요구사항 ID는 [02_요구사항.md](02_요구사항.md), 기술 결정은 [03_기술_스펙.md](03_기술_스펙.md). 2026-09-16 v0.1.

## What This Is

WHENNOTE는 떠오른 생각을 전역 단축키 한 번으로 적어 두고, 나중에 키워드 절반만 기억해도 다시 찾는 트레이 상주 메모 앱이다. 할 일·마감·일정은 다루지 않는다. 그것은 WHENWORK의 역할이고, 두 앱은 같은 사람의 트레이에 나란히 산다.

## Core Value

**어느 창에 있든 1초 안에 적기 시작할 수 있고, 적은 것은 절대 잃지 않으며, 몇 달 뒤에도 몇 글자로 다시 찾는다.**

세 문장 중 앞의 둘은 WHENWORK가 이미 증명한 방식(전역 단축키·큐 선기록·강제 종료 스모크)을 그대로 가져온다. 마지막 하나가 이 앱의 고유 가치다. 메모 앱은 기능이 부족해서가 아니라 꺼내기 귀찮고 다시 못 찾아서 버려진다.

## 페르소나

| | 특성 | 도출되는 요구 |
|---|---|---|
| 주 사용자 | 한국어 사용, Windows 11 또는 macOS, 하루에 여러 번 짧은 생각·링크·회의 내용을 남긴다. WHENWORK 사용자와 같은 사람 | 한글 초성·부분 문자열 검색, 두 앱의 단축키·조작 체계가 충돌하지 않고 비슷해야 함 |
| 상황 | 화상회의 중, 코드 읽는 중, 브라우저에서 링크를 발견한 순간 | 항상-위 소형 창, 클립보드 감지, 저장 버튼 없음 |
| 태도 | 정리에 시간 쓰지 않는다. 폴더를 만들면 안 쓴다 | 폴더 없음. 태그(#)와 링크([[ ]])만. 최근 열어본 순이 기본 정렬 |

## 스코프

### 포함 (v1)

- 전역 단축키로 뜨는 다중 행 퀵캡처 창(항상-위 토글, Esc가 저장)
- 메인 창: 검색창이 곧 입력창. 결과가 없으면 그 문장이 새 메모가 된다
- 검색: 부분 문자열, 한글 초성, 태그 필터, 최근 열어본 순 정렬
- 태그 `#`, 메모 간 링크 `[[제목]]`, 백링크 표시
- 고정·아카이브·소프트 삭제·복구
- 최소 마크다운 렌더링(제목·강조·목록·코드·링크)
- 이미지 붙이기(클립보드 → 파일 저장 → 메모에 링크)
- JSON 내보내기·가져오기(WHENWORK와 같은 방식) + 마크다운 폴더 내보내기
- Windows·macOS 설치 파일, GitHub Releases 미서명 배포, 자동 업데이트 알림

### 제외

| 기능 | 이유 |
|---|---|
| 할 일·체크박스·마감·리마인더·브리핑 | WHENWORK의 역할. 기능 중복은 두 앱 모두를 흐린다 (2026-09-16 결정) |
| 폴더·노트북 계층 | 페르소나가 정리에 시간을 쓰지 않는다. 태그와 링크로 충분하다 |
| 클라우드 동기화·계정 | 1인 1PC. 내보내기·가져오기가 이동을 대신한다 (WHENWORK와 동일) |
| AI 요약·자동 태그 | 구독·CLI·API 키 전제가 "설치 파일 하나"에 어긋난다. v2 후보 |
| 리치 텍스트 편집기(WYSIWYG) | 렌더러 비대화. 편집은 플레인 텍스트, 보기는 마크다운 |
| 사람이 직접 편집하는 파일을 원본으로 삼는 저장 | 동시 수정·손상을 앱이 감당해야 한다. 내장 저장소 + 마크다운 내보내기로 대신 (WHENWORK Out of Scope 승계, 결정은 [03 §저장소](03_기술_스펙.md)) |
| 협업·공유·권한 | 원 설계 전면 배제 |

## WHENWORK와의 경계

| | WHENWORK | WHENNOTE |
|---|---|---|
| 던지는 것 | 해야 할 일 (한 줄) | 생각·정보 (여러 줄) |
| 시간 축 | 마감·오늘·대기 | 없음. 작성일과 마지막 열어본 시각만 |
| 끝나는 상태 | 완료 | 없음. 아카이브만 |
| 기본 단축키 | `Ctrl+Alt+Space` | `Ctrl+Alt+N` (충돌 방지, 결정 필요 → [오픈이슈 #1](03_기술_스펙.md#오픈이슈)) |
| 공유하는 것 | 스택, 모듈 구조, 큐·저장소 패턴, 디자인 토큰, 빌드·릴리스 파이프라인, 테스트 방식 | |

두 앱은 코드를 공유하지 않는다(모노레포·공용 패키지 없음). 검증된 모듈을 복사해 시작하고 각자 진화한다. 공용화는 세 번째 앱이 생길 때 다시 본다.
