# WHENNOTE — 요구사항

> 프로젝트 정의는 [01_프로젝트.md](01_프로젝트.md), 기술 결정은 [03_기술_스펙.md](03_기술_스펙.md). ID 체계와 문서 형식은 WHENWORK `docs/03_요구사항.md`를 따른다. 2026-09-16 정의. 체크는 자동 테스트가 증명한 것만 — UI 항목은 실사용으로 확인한 뒤 체크한다.

**Core Value:** 어느 창에 있든 1초 안에 적기 시작할 수 있고, 적은 것은 절대 잃지 않으며, 몇 달 뒤에도 몇 글자로 다시 찾는다.

## v1 Requirements

### 캡처 (CAP)

- [ ] **CAP-01**: 전역 단축키로 어느 화면에서든 다중 행 퀵캡처 창이 뜬다. 첫 실행부터 설정 없이 동작한다
- [ ] **CAP-02**: 저장 버튼이 없다. `Esc`로 창을 닫으면 저장되고, 빈 내용이면 아무것도 만들지 않는다. `Ctrl+Enter`는 저장 후 메인 창에서 그 메모를 이어서 편집한다
- [ ] **CAP-03**: 제목을 강제하지 않는다. 첫 줄이 제목이고, 첫 줄이 없으면 작성 시각이 제목이다
- [x] **CAP-04**: 캡처는 저장소 상태와 무관하게 절대 실패하지 않는다. 로컬 큐에 먼저 기록되고 저장소 반영이 실패하면 다음 실행에 자동 반영된다 (WHENWORK STOR-02 승계)
- [x] **CAP-05**: 캡처 직후 앱을 강제 종료해도 그 메모는 유실되지 않는다. 이를 재현하는 자동 테스트가 있다 (WHENWORK STOR-03 승계)
- [ ] **CAP-06**: 퀵캡처 창은 항상-위 토글이 있고, 켜 두면 다른 창을 눌러도 닫히지 않는다. 끄면 포커스를 잃을 때 저장 후 닫힌다
- [ ] **CAP-07**: 퀵캡처 창을 열 때 클립보드에 URL 또는 텍스트가 있으면 한 줄 제안을 보여 준다. `Ctrl+V` 한 번으로 붙는다. 제안은 보기만 하고 자동으로 넣지 않는다 — 2026-09-16 구현(이미지는 "메인 창에서 붙이세요" 안내), 실사용 확인 전
- [ ] **CAP-08**: 퀵캡처 창의 위치·크기를 기억한다 (WHENWORK place.mjs 승계)

### 메인 창 (MAIN)

- [ ] **MAIN-01**: 메인 창을 열면 커서가 검색창에 있다. 검색창은 입력창이기도 하다: 타이핑하면 즉시 결과가 바뀌고, `Shift+Enter`로 입력한 문장이 새 메모의 첫 줄이 된다
- [ ] **MAIN-02**: 결과 목록은 기본이 최근 열어본 순이고, 항목마다 제목·요약 한 줄·상대 시각·태그를 보여 준다. 일치한 글자는 강조된다
- [ ] **MAIN-03**: 결과를 선택하면 오른쪽에 메모가 열리고 바로 편집된다. 편집 내용은 저장 버튼 없이 자동 저장된다(디바운스). 저장 여부가 화면 어딘가에 드러난다
- [ ] **MAIN-04**: 메모 보기는 최소 마크다운을 렌더링한다 — 제목, 굵게·기울임·취소선, 목록(중첩·번호), 체크박스(보기에서 눌러 토글, 할 일 관리 기능은 아님), 인용, 인라인 코드·코드 블록, 구분선, 외부 링크·URL(기본 브라우저로), `[[메모 링크]]`, `#태그`, 붙인 이미지. 표·HTML·각주는 다루지 않는다 (2026-09-16 개정)
- [x] **MAIN-05**: 메모를 고정·아카이브·삭제·복구할 수 있다. 삭제는 소프트 삭제이고 30일 뒤 정리된다 (WHENWORK 항목 삭제 규칙 승계)
- [ ] **MAIN-06**: 키보드만으로 검색→선택→편집→닫기까지 끝난다. `Ctrl+/`로 전체 키맵을 본다(`?`는 검색창에서 글자라 못 쓴다). `Ctrl+Delete`로 선택한 메모를 지우고, `Shift+↑↓`로 고정한 메모끼리 순서를 바꾼다 (WHENWORK 조작 체계 승계)
- [ ] **MAIN-07**: 트레이(macOS 메뉴바) 아이콘 클릭 또는 단축키로 메인 창을 열고, 창 위치·크기를 기억한다
- [ ] **MAIN-08**: 클립보드 이미지를 `Ctrl+V`로 붙이면 앱 데이터 폴더에 파일로 저장되고 메모에 이미지 링크가 들어간다. 보기에서 렌더링된다 — 2026-09-16 구현(wn-attach:// 스킴, D-11), 실사용 확인 전

### 검색 (SRCH)

- [x] **SRCH-01**: 부분 문자열 검색이 된다. "캐시"로 "캐시무효화"가 찾아진다. 단어 경계에 의존하지 않는다
- [x] **SRCH-02**: 한글 초성 검색이 된다. "ㅎㅇ"로 "회의"가 찾아진다
- [x] **SRCH-03**: 태그로 필터할 수 있다. `#태그`를 검색어에 넣거나 태그 칩을 눌러 좁힌다. 여러 태그는 AND
- [x] **SRCH-04**: 결과는 메모 1,000건에서 키 입력 후 50ms 안에 갱신된다. 이를 측정하는 테스트가 있다
- [x] **SRCH-05**: 검색어가 비어 있으면 최근 열어본 순 전체 목록이고, 고정 메모가 맨 위에 온다

### 태그·링크 (LINK)

- [x] **LINK-01**: 본문의 `#태그`가 태그로 인식된다. 태그는 본문 밖에서 따로 관리하지 않는다. `#`가 숫자로만 이어지면(`#201`) 태그가 아니다
- [x] **LINK-02**: 본문의 `[[제목]]`이 다른 메모로의 링크로 렌더링된다. 클릭하면 그 메모가 열리고, 없는 제목이면 그 제목으로 새 메모를 만든다
- [x] **LINK-03**: 메모 하단에 이 메모를 가리키는 메모 목록(백링크)이 보인다
- [x] **LINK-04**: 메모의 첫 줄(제목)을 바꾸면 그 메모를 가리키던 `[[구제목]]`은 깨지지 않고 계속 같은 메모를 가리킨다

### 저장소 (STOR)

- [x] **STOR-01**: 앱은 외부 DB·컨테이너 없이 앱 데이터 폴더 안의 내장 저장소(단일 파일)에 메모·태그·링크·이벤트를 저장한다
- [x] **STOR-02**: 저장소 스키마에 버전이 있고, 앱 업데이트 시 사용자 개입 없이 자동 마이그레이션된다. 이행 직전 자동 백업이 남는다
- [x] **STOR-03**: 자신보다 높은 스키마 버전의 DB를 만나면 쓰지 않고 안내한다. 손상된 DB는 지우지 않고 옆에 보관한다 (WHENWORK D-13·D-15 승계)
- [x] **STOR-04**: 이미지 파일은 저장소 파일 옆 `attachments/` 폴더에 저장되고, 메모가 영구 삭제될 때 함께 정리된다

### 내보내기·가져오기 (DATA)

- [x] **DATA-01**: 설정에서 전체 데이터를 사람이 읽을 수 있는 JSON 파일 하나로 내보낼 수 있다. 이미지는 같은 폴더에 함께 나간다
- [x] **DATA-02**: 내보낸 JSON을 다른 PC의 앱에서 가져오면 같은 상태로 복원된다. 왕복 테스트가 있다. 가져오기 직전 자동 백업된다
- [x] **DATA-03**: 설정에서 전체 메모를 마크다운 파일 폴더(메모 하나 = `.md` 하나, 태그는 frontmatter)로 내보낼 수 있다. 읽기 전용 내보내기이며 가져오기는 지원하지 않는다

### 첫 실행·플랫폼 (PLAT)

- [ ] **PLAT-01**: 설치 후 첫 실행에 아무 설정 화면 없이 단축키 캡처가 바로 동작한다
- [ ] **PLAT-02**: 단축키 등록이 실패하면(WHENWORK 등 다른 앱과 충돌 포함) 사용자에게 알리고 설정에서 재바인딩할 수 있다. 바꾼 조합의 등록 성공 여부를 확인한다 — 설정 화면(`Ctrl+,`)에서 칸을 누르고 조합을 누르면 바로 바뀐다(2026-09-16 구현, 실사용 확인 전)
- [ ] **PLAT-03**: 설정에 로그인 시 자동 실행 토글이 있다 — 설정 화면과 트레이 메뉴 양쪽(2026-09-16 구현, 설치본에서만 동작)
- [ ] **PLAT-04**: 첫 실행에 트레이 아이콘 위치와 단축키를 OS별 문구로 한 번 안내한다
- [ ] **PLAT-05**: macOS에서 메뉴바 상주(독 아이콘 없음)·전역 단축키·창 위치 기억이 동작한다. OS 분기는 `main/platform/` 안에만 있다 (WHENWORK PLAT-06 승계)
- [ ] **PLAT-06**: WHENWORK와 같은 PC에서 동시에 실행돼도 트레이·단축키·데이터 폴더가 서로 간섭하지 않는다

### 릴리스 (REL)

- [ ] **REL-01**: Windows NSIS와 macOS dmg·zip(arm64·x64)이 같은 electron-builder 설정에서 빌드된다
- [ ] **REL-02**: GitHub Actions가 태그 푸시 시 두 OS를 빌드해 GitHub Releases 드래프트에 올린다. 사람이 공개한다
- [ ] **REL-03**: 앱은 새 버전을 감지해 알리고, Windows는 종료 시 설치, macOS는 다운로드 안내를 한다 (WHENWORK update.mjs 승계)
- [ ] **REL-04**: README에 설치·미서명 첫 실행 우회·단축키·데이터 위치가 있다
- [ ] **REL-05**: 패키징된 설치본에서 스모크 테스트가 Windows·macOS 모두 통과한다

### 완료 판정 (DONE)
